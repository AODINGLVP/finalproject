## PRJ-P0-02：让自动避让保持行为树层级，同时保留自由拖动

### 失败复现

先把 L3、L4、L5 写成自动断言。修改实现前，31、61、121、241、364 节点的全零坐标树在普通卡片、紧凑卡片、语义概览和阈值缩放中共出现 57 项失败。失败集中在：

- 子节点没有位于父节点下方；
- 完整深度行没有与上一行分开；
- 屏幕上的兄弟顺序与资源执行顺序不一致。

这证明“零重叠”与“仍然是一棵可读的树”并不是同一件事。

### 第一次修复

- 只在多个节点完全重叠、已经不存在可保留的相对位置时，按照行为树深度分行临时展开。
- 每一行按照资源中的稳定顺序排列，卡片之间使用实际最大卡片尺寸加 24 像素间距。
- 普通、没有碰撞的自由布局仍保持原位，不会自动变成固定格式。
- 直接相连的父子卡片发生碰撞时，沿纵向按父上子下避让；不相关卡片仍按最小移动方向进行局部避让。
- 拖动节点继续固定在指针指定位置，其他节点只使用临时显示偏移，不写回资源。
- 完全相同坐标的兄弟节点增加稳定的资源顺序回退，避免执行顺序由不确定排序决定。
- 活动插件和可分发模板同步修改。

### 验证结果

- 缩放与拖动专项：`BT_ZOOM_DRAG_LAYOUT_TEST_SUMMARY passed=1311 failed=0`。
- 编辑器功能：`BT_EDITOR_TEST_SUMMARY passed=250 failed=0`。
- 运行时与资源：`BT_TEST_SUMMARY passed=154 failed=0`。
- 覆盖 31、61、121、241、364 节点。
- 覆盖最小、普通、最大和语义阈值缩放。
- 覆盖普通卡片、紧凑卡片、语义概览、父子直接碰撞、全零坐标恢复。
- 活动插件与模板的修改文件 SHA-256 一致。
- 结构、参数、执行顺序、非拖动节点资源坐标、撤销/重做和保存/重载保持不变。

**状态：已完成。尝试次数：1/3。** 没有触发停止边界。

## PRJ-P0-03：检查并改善连线可读性

### 失败复现

新增一棵确定性测试树：父节点到目标子节点的原始通道会穿过另一个子节点卡片。修改实现前，编辑器测试得到 `250 passed / 1 failed`，失败项就是“默认连线避开无关卡片”。这证明原来的自定义连线虽然能够点击和断开，但没有检查路径中间是否存在其他卡片。

### 最终保留的实现

- `Display > Advanced Display > Edge Obstacle Avoidance` 默认开启，也可以独立关闭并安全恢复原始基线路由。
- 没有遮挡时继续使用原来的圆角通道、正交线或捆绑线，不改变正常连线外观。
- 检测到遮挡时，依次尝试卡片上方、下方和画布侧面的无碰撞通道，选择较短的可用路线。
- 路线始终从父节点底部端口开始，并在子节点顶部端口结束。
- 点击检测使用屏幕上实际绘制的绕行路线，因此右键断开、撤销和重做仍然有效。
- 路由缓存同时记录所有可见卡片的位置和尺寸；移动第三张卡片也会使旧路线失效。
- 活动插件与可分发模板同步修改。

### 测试范围和结果

- 编辑器功能：`BT_EDITOR_TEST_SUMMARY passed=263 failed=0`。
- 缩放与拖动：`BT_ZOOM_DRAG_LAYOUT_TEST_SUMMARY passed=1311 failed=0`。
- 运行时与资源：`BT_TEST_SUMMARY passed=154 failed=0`。
- 真实 GPU 视觉回归：`BT_VISUAL_TEST_SUMMARY passed=140 failed=0`。
- 普通卡片与紧凑卡片均覆盖最小、标准和最大缩放，端点与端口保持一致。
- 检查了不同子分支不会形成完全相同的整条路线。
- 关闭开关能够复现穿卡片基线；重新开启后绕开卡片，且树结构、执行顺序和资源坐标不变。
- 真实 241 节点树的同视角截图：
  - `testgame/testgame/test_results/visual/11a1_playable_241_edge_baseline.png`
  - `testgame/testgame/test_results/visual/11a2_playable_241_edge_avoidance.png`

### 停止边界记录

第二种尝试扩大为“对全部屏幕外卡片寻找全画布出口”，紧凑 241 节点诊断能够得到零穿越，但完整缩放矩阵持续高负载五分钟仍未结束。这会损害本项目最关心的大树编辑体验，因此该尝试已经完全回退，没有进入最终实现。最终保留轻量的按需局部绕行，并以主要可见父子连线为验收边界。

## PRJ-P1-04：尝试“始终使用曲线”的连线方案

### 实现和使用边界

- 新增 `Display > Advanced Display > Always Curved Edges (Experiment)`。
- 开关默认关闭，不改变现有项目的推荐显示。
- 开启后每条父子连线使用固定采样的三次 Bezier 曲线，并保持原来的父节点底部和子节点顶部端口。
- 为保证“始终曲线”的实验条件真实成立，它在开启期间暂时优先于正交、捆绑和障碍避让样式，但不修改这些开关的保存状态。
- 关闭后立即恢复开启实验前的正交、捆绑和障碍避让组合；树结构、节点坐标和子节点执行顺序不变。

### 241 节点固定场景结果

实验复用 PRJ-P0-03 的真实 241 节点树、相同三张卡片位置、相同缩放和相同滚动位置：

| 条件 | 穿过固定无关卡片 | 路线折线近似长度 |
| --- | ---: | ---: |
| 当前推荐的障碍避让 | 0 | 1001.0 |
| 始终曲线 | 1 | 750.4 |

曲线的几何长度较短，曲线形状也与当前通道明显不同；但是它重新穿过了中间卡片。因此，这个场景没有支持“始终曲线比当前避让更清楚”的结论。视觉对照只说明绘制结果不同，不能代替真人对可读性的评价。

对照截图：

- 当前方案：`testgame/testgame/test_results/visual/11a2_playable_241_edge_avoidance.png`
- 始终曲线：`testgame/testgame/test_results/visual/11a3_playable_241_always_curved.png`

结论是**作为可选实验开关保留，默认关闭**。用户可以自行观察不同树上的效果，但正常编辑仍建议使用默认障碍避让。

### 验证结果

- 编辑器功能：`BT_EDITOR_TEST_SUMMARY passed=267 failed=0`。
- 真实 GPU 视觉回归：`BT_VISUAL_TEST_SUMMARY passed=146 failed=0`，进程正常退出。
- 覆盖曲线优先级、端点、点击命中、关闭恢复、树顺序不变、配置持久化和 241 节点固定相机截图。
- 视觉测试遇到过 Windows 对已存在 PNG 的一次短暂写入失败；测试现在最多重试三帧，并按父子顺序安全释放真实渲染视口。最终运行记录了一次重试后成功，不隐藏持续写入失败。

### 文献依据

Kai Xu、Chris Rooney、Peter Passmore、Dong-Han Ham 与 Phong H. Nguyen 在 2012 年发表 *A User Study on Curved Edges in Graph Visualization*（IEEE Transactions on Visualization and Computer Graphics, 18(12), 2449–2456；DOI: [10.1109/TVCG.2012.189](https://doi.org/10.1109/TVCG.2012.189)；[PubMed 记录](https://pubmed.ncbi.nlm.nih.gov/26357153/)）。论文通过两个实验比较直线、不同曲率和混合边，报告不同边样式之间存在显著性能差异。它支持“曲率需要通过具体任务验证”，而不是预设曲线一定更好。

## PRJ-P1-05：尝试半透明节点卡片

### 实现方式

- 新增 `Display > Advanced Display > Translucent Cards (Experiment)`，默认关闭。
- 固定透明规则为“主题背景原 alpha × 0.72”，所有截图和所有卡片使用同一个系数。
- 只复制并覆盖 Godot `GraphNode` 支持的背景 `StyleBoxFlat`，不调整整张卡片的 `modulate` 或 `self_modulate`。
- 文字、边框、上下端口、节点类型状态条、运行时颜色和选中状态保持原 alpha。
- 搜索继续使用 `self_modulate`，Live Debug 分支淡化继续使用 `modulate`；两者能够与背景透明度组合，而不会互相覆盖。
- 关闭后删除实验样式并恢复启用前的主题覆盖，不留下透明状态。
- 活动插件与可分发模板同步修改。

### 固定 241 节点视觉结果

对照复用 PRJ-P1-04 的真实 241 节点树、始终曲线路径、节点位置、缩放和滚动位置，唯一差别是背景透明开关：

- 不透明：`testgame/testgame/test_results/visual/11a3_playable_241_always_curved.png`
- 半透明：`testgame/testgame/test_results/visual/11a4_playable_241_translucent_cards.png`

真实渲染图中，连线路线本身完全相同并继续经过卡片后方；透明背景使卡片内部 21,059 个像素发生可测变化。作为文字与控件没有被整体淡化的检查，卡片区域内亮度不低于 0.72 的像素从 840 个变为 851 个，没有减少。代码层断言同时确认文字、状态条和端口的 alpha 仍为 1.0，选中背景也使用相同 0.72 系数。

这个结果说明功能确实只改变背景并允许更多后方内容参与合成，但不能据此声称真人阅读一定更轻松。后方连线也可能与文字笔画混在一起。因此结论是**作为可选实验开关保留，默认关闭**。

### 验证结果

- 编辑器功能：`BT_EDITOR_TEST_SUMMARY passed=275 failed=0`。
- 真实 GPU 视觉回归：`BT_VISUAL_TEST_SUMMARY passed=154 failed=0`，进程正常退出。
- 运行时与资源：`BT_TEST_SUMMARY passed=154 failed=0`。

- 最初两次视觉断言无法稳定把 GraphEdit 内部路线点换算为单个屏幕像素；最终改为联合验证“路线保持且穿过卡片、背景 alpha 固定改变、完整卡片区域像素变化、亮色文字像素保留”，没有调整透明参数来迁就测试。

### 可读性资料

W3C 的 [WCAG 2.2 Failure F83](https://www.w3.org/WAI/WCAG22/Techniques/failures/F83.html) 明确指出，当背景图形与前景文字对比不足时，背景线条可能与字母笔画混淆。该资料适用于任何产生视觉输出的技术。它不直接评价本 Godot 插件，但支持本项目的谨慎决定：保持文字完全不透明、提供一键关闭，并不把半透明背景设为默认。

**状态：已完成。尝试次数：1/3。** 功能实现一次通过；视觉取样断言经过两次有界修正后通过，没有触发停止边界。
