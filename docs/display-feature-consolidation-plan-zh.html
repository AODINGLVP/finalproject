1. 当前问题不是单纯“数量多”

五种不同性质的东西被放进了同一个 Display 菜单。

实现细节暴露给普通用户

Single Connection Rendering、Auto Spacing 和 Zoom View Anchor 更像保证显示正确的内部机制，而不是日常偏好。

有真实的覆盖与优先级

Compact 会覆盖 Semantic Zoom 的信息层；连线同时勾选时实际按 Curved > Bundled > Orthogonal 执行，但菜单没有说明。

功能放错位置或重复

Multi-column、Stable 属于 Auto Arrange；Active Path、Dimming、Failure、Path Summary 属于运行调试。Dimming 和 Failure 还在 Debug 重复出现。

3. 明确的关联关系

“能一起工作”不等于“应该变成同一个开关”。

卡片详情

强合并
CompactSemantic ZoomDecorator Badges

Compact 开启时会强制最低信息层，使 Semantic Zoom 基本失效。建议改成 Full／Adaptive／Compact 三选一；Decorator Badges 随完整信息层出现，并保留高级覆盖。

焦点与布局保护

内部联动
FisheyeAuto SpacingZoom Anchor

Fisheye 是用户效果；Auto Spacing 与 Zoom Anchor 是防重叠和保持视野的支撑机制。保留 Focus Lens 一个普通开关，支撑项转入高级诊断。

节点识别

适合模式化
Type EncodingColorblind PaletteKeyboard Search

建议改成 Standard／Shape + Color／Accessible 三选一。Accessible 自动包含形状冗余和色盲友好配色；原始独立状态仍留在 Advanced。

连线显示

必须单选
Default ChannelOrthogonalBundledCurved

当前三个复选框可以同时为真，但只有最高优先级生效。改成单选可消除隐式覆盖；Single Connection 作为自定义连线基线，退到 Diagnostics。

运行解释

移动分组
Active PathDimmingFailure ReasonsPath Summary

四项都依赖 Live Debug 快照，应只在 Debug 出现。它们用途不同，建议放在同一组，但不要强制绑成一个总开关。

结构与导航

分组但不合并
CollapseFocusSearchBreadcrumbMinimap

它们都帮助处理大树，但改变范围不同：Search 负责定位，Focus 负责临时裁剪，Collapse 保存每个分支状态，Minimap 提供全局方向。只能放近一些，不能绑定执行。

自动排布策略

移到 Layout
Multi-columnStable LayoutAuto Arrange

Multi-column 和 Stable 只在 Auto Arrange 时生效，不是持续显示效果。建议变成 Layout 中明确命名的排布命令或排布选项。

实验与画布偏好

单独收纳
Curved ExperimentTranslucent CardsGrid

实验项默认关闭并集中到 Experimental。Grid 是个人画布偏好，应保留独立，不与任何可读性模式强绑。

4. 三套整合方案

点击切换，比较改动强度和风险。

A · 只重新分组

不改变任何开关语义，仅把平铺列表拆成 Cards、Navigation、Connections、Canvas、Experimental 等子菜单。

最低风险

优点

  • 实现和迁移最简单。
  • 现有测试基本可原样保留。
  • 所有独立实验开关仍直接可见。

不足

  • 用户仍会面对约 14 个以上开关。
  • Compact 与 Semantic、三种连线的冲突仍存在。
  • 只是“藏整齐”，没有真正减少决策。

B · 任务导向的普通层 + 可展开高级层

普通用户看到能理解的结果型控件；底层开关仍独立存在，用于兼容、诊断和论文实验。

推荐

优点

  • 真正消除冗余状态和隐式优先级。
  • 不依赖难以预测的大型“模式”。
  • 保持功能可单独测试、关闭和回退。
  • 不会自动修改树坐标、折叠状态或执行顺序。

代价

  • 需要配置迁移和新菜单测试。
  • Advanced 需要分类，不能继续平铺。
  • 合并控件必须定义清楚混合旧状态的显示规则。

C · Editing／Overview／Inspect／Runtime 四种模式

用户只选择任务模式，一次切换多个显示状态；任何手动修改后显示为 Custom。

最激进

优点

  • 表面选项最少。
  • 新用户容易快速得到一个可用组合。
  • 适合作为额外 Presets，而非唯一入口。

主要风险

  • 一次改变很多状态，结果难预测。
  • 不利于论文中单独比较显示功能。
  • 不得在模式切换时自动 Collapse All 或 Auto Arrange，否则会改变资源或历史。
  • 无障碍偏好不能被普通模式覆盖。

6. 哪些能合并，哪些只能分组

避免为了减少按钮而制造新的隐式行为。

关系建议理由
Compact + Semantic Zoom合并为三选一Compact 本来就覆盖语义层。Full／Adaptive／Compact 能直接表达用户想看到多少信息。
Orthogonal + Bundled + Curved改为路线单选当前同时勾选时只有最高优先级生效，多个复选框会显示错误的心理模型。
Type Encoding + Accessibility合并为编码模式Accessible 应包含形状冗余和友好配色；高级层仍可单独覆盖。
Fisheye + Auto Spacing + Zoom Anchor一个效果 + 后台保护用户选择局部放大，插件自动保证避让与视野稳定；不需要让用户手动拼装依赖。
Collapse + Focus只分组，不合并Collapse 保存每个分支状态；Focus 是临时只看一个分支及祖先路径。
Search + Focus / Collapse保持独立Search 定位全树；不能因为搜索就静默裁剪或改写折叠状态。
Minimap + Fisheye保持独立前者提供全局方向，后者提供指针附近细节；屏幕占用和动态效果偏好不同。
Auto Arrange + Auto Spacing绝不能合并Auto Arrange 写入资源坐标和历史；Auto Spacing 只产生临时 visual offset。
运行调试四项同组、分别开关它们共享 Live Debug 数据，但用户可能只要路径、不想淡化，或只想看失败原因。
Translucent Cards + Branch Dimming不要合并两者都涉及透明度，但前者是实验性卡片外观，后者表达运行状态，语义完全不同。

7. 后续实施时的迁移与安全边界

保证界面精简不破坏现有树、设置和实验。

Card Detail 迁移

旧 Compact=true → Compact；否则 Semantic=true → Adaptive；其余 → Full。若两者同时开启，Compact 优先，符合当前实际效果。

Node Encoding 迁移

Accessibility=true → Accessible；否则 Type Encoding=true → Shape + Color；其余 → Standard。

Connection Style 迁移

Curved > Bundled > Orthogonal > Default，严格按当前代码优先级得到唯一有效模式，再清理无效的重复状态。

底层独立开关保留

Auto Spacing、Zoom Anchor、Single Connection 等移到 Advanced／Diagnostics，仍能单独关闭、复位和自动测试。

不改变树资源

菜单迁移不能修改节点坐标、父子关系、左右执行顺序、Decorator 归属、折叠资源状态或 .tres 保存路径。

Search 与 Collapse 能力

普通界面可取消“是否允许使用”的总开关。旧 Search=false 不能让升级后的搜索框无故不可用；旧 Collapse=false 首次升级先按完整树显示且不写回 .tres，避免旧树突然隐藏。

配置版本与回退

给 view config 增加版本号，至少兼容读取一版旧键；提供 Reset Display Defaults，并验证关闭功能后恢复基线。

测试范围

覆盖菜单映射、旧配置迁移、每种单选模式、Advanced 独立覆盖、保存／重载，以及 31、61、121、241、364 节点树的结构与显示回归。

论文实验约束： 即使普通菜单改成组合控件，底层条件仍应能独立设置，才能继续复现 Baseline、Compact、Overview、Search、Focus 和 Collapse 等受控条件。
