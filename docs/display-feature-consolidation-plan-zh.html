4. 哪些功能适合整合

下面只说明有明确关系的剩余功能，帮助判断是合并成一个模式，还是继续独立存在。

卡片详情：Compact + Semantic Zoom

两者都控制卡片里显示多少信息。Compact 是固定精简；Semantic Zoom 会按缩放自动切换信息层。可以合并成 Full、Adaptive、Compact 三种详情模式。

共同点都不修改资源
冲突Compact 会压过语义层

局部观察：Fisheye + Auto Spacing + Zoom Anchor

Fisheye 是用户直接感知的放大效果；Auto Spacing 防止放大后的卡片遮挡；Zoom Anchor 防止临时布局变化把观察位置推走。后两项更像后台保护。

可整合一个 Focus Lens 入口
安全边界均不写资源坐标

节点识别：Type Encoding + Accessibility

前者增加形状和图标，后者改变配色。两种提示可组合成 Standard、Shape + Color、Accessible 三种识别模式。

当前问题搜索快捷键与配色绑定
建议快捷键独立为常用操作

结构查看：Collapse + Breadcrumb + Focus

Collapse 减少同时显示的后代；Focus 临时只看一个分支；Breadcrumb 显示当前选择的祖先路径。它们互相补充，但保存状态不同，不适合强制同步。

会保存Collapse 状态
临时状态Focus 与 Breadcrumb

连接渲染：Single Connection Rendering

它不是线路形状，而是决定使用插件的单条自定义连接，还是恢复 Godot 原生连接层。更适合作为后台实现或诊断选项。

影响绘制、命中和断开
不影响树结构与执行顺序

自动排布：Stable Layout + Auto Arrange

Stable Layout 只有在执行 Auto Arrange 时才有意义。它会尽量恢复仍然合法的旧位置，减少大范围跳动，因此更像排布策略。

触发执行 Auto Arrange
结果坐标写入资源和历史

实验外观：Translucent Cards

它只降低卡片背景透明度，同时保持文字、端口和状态色清晰。主要用于观察卡片后方内容，复杂图中也可能增加视觉噪声。

优点可看见卡片后方
风险复杂树可能更杂乱
