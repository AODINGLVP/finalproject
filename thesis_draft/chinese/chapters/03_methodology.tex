\chapter{研究方法}
\label{ch:methodology}

\section{研究策略}

本研究采用设计科学与软件工程结合的策略。研究产物是 Godot 4.6 插件和可执行演示；研究知识来自把行为树语义和可视化文献中的设计要求落实为系统，再测量其正确性、显示属性、编写交互和开发者任务可用性。运行时性能仅保留为次要工程证据，而不是主要成功标准。迭代开发是必要的，因为编辑器集成暴露了单独算法中看不到的问题，例如坐标空间错误、残留 Transform、重复连线和半写入调试快照。

过程分为五个阶段：首先把导师会议要求和论文规范转化为验收门槛；其次建立最小可执行行为树核心和游戏集成；然后加入编辑操作和 Live Debug；随后将显示技术放在独立开关后，每次增加功能都测试关闭与复位；最后用确定性工作负载和分层测试比较完成系统与自身基线。后续任务完成后重新运行完整回归，以防图重建或资源复制改动破坏早期功能。

\section{实验因素与数据集}

三棵确定性生成树分别包含 31、121 和 364 个节点，代表易于编辑的小树、超过导师所提约 50 节点可读性边界的中型树，以及大型压力场景。三棵树使用相同生成规则，使规模成为主要差异；固定目标节点则保证搜索和实时路径截图可重复。另有一棵生态有效性测试树包含 241 个资源节点，其中 202 个为画布卡片，39 个为附着的 Decorator。与生成树不同，它就是可玩敌人实际加载的资源，包含恢复、方向近战、越障跳跃、梯子攀爬、远程投射物、压迫推进、追击、最后位置搜索、返回、巡逻和待机行为。

显示实验以完整细节节点--连线图为基线，主要条件为 Compact、Semantic Zoom、Search、Subtree Focus、Subtree Collapse、Fisheye 和 Enhanced Minimap。其余功能通过 19 项开关循环覆盖。指标定义如下：可见比例为可见节点数除以总数；卡片面积为可见卡片最小宽高乘积之和；信息字段表示当前语义层保留的代表字段；淡化节点数表示搜索或路径聚焦降低显著性的节点；鱼眼增益为目标卡片内部倍率；概览覆盖率为小地图表示节点数除以总数；操作时间为当前机器上的重建、更新或开关周期时间。

这些是界面仪器指标，不是心理指标。人体实验另外记录任务完成时间、误选、缩放和平移次数、成功率，以及七点评分的可读性与认知负荷。

\section{可玩树显示实验}

生态显示实验在 NVIDIA GeForce RTX 5070 Laptop GPU 上使用 Godot 4.6 OpenGL Compatibility 渲染器和 1600×900 的 \texttt{SubViewport}，加载固定的 241 节点可玩资源。六个条件为 Baseline、Compact Cards、Optimized Overview、Optimized Search、Subtree Focus 和 Context Collapse。Search 固定定位 \texttt{Patrol Route Choice}，Focus 固定选择 \texttt{11 Layered Patrol}。每个条件先预热三次，再记录 30 次。每轮测量把条件顺序循环移动一次，因此六个条件在六种序位上各出现五次，以减少时间和温度漂移，同时避免不可复现的随机顺序。

每次观测都从同一完全展开树、空查询、100\% 缩放和无焦点状态开始。脚本记录资源节点数、卡片数、可见比例、图边界面积、卡片面积、重叠对数、信息字段数、淡化卡片数和交互时间。原始数据包含 180 次观测；汇总报告中位数、第一/第三四分位数和第 95 百分位。由于各条件触发的操作不同，时间值用于描述响应范围，而不构成共同性能排名。断言要求资源恰为 241 个、基线恰为 202 张卡片、所有条件零重叠且不修改保存位置；Compact 面积至少减少 40\%，Overview 至少减少 70\%，Search 至少淡化 95\% 的非目标卡片，Focus 与 Collapse 至少减少 70\% 的卡片。

第二项同任务比较让同一张卡片沿固定路径移动 240 个指针采样点。基线与优化版本使用相同树、卡片、路径和渲染器；一次预热后各测五轮，保留总时间与每采样点时间的中位数。该测试测量的是编写操作中的处理延迟，而不是行为树运行资源效率或用户感知流畅度。

运行时实验交叉三种树规模、1/10/50 个 Runner 和缓存开/关。每个组合预热后测量七次。测试调整 Tick 数，使各条件执行一个有界且大致可比的总工作负载。使用 Tick 均值的中位数，以降低临时调度噪声影响；缓存和非缓存还必须返回相同终态。

\section{正确性与集成评估}

测试分为五个核心层。资源/运行时测试检查结构、节点语义、Decorator、Actor、Schema、调试快照和缓存失效；编辑器 GUI 测试实例化插件并检查创建、拖拽、连接、类型字段、保存重载、撤销重做和开关；基础游戏测试检查玩家与敌人交互；复杂竞技场测试覆盖索敌、响应式防御、方向近战、远程投射物、障碍感知与跳跃、对高处玩家的梯子追击、丢失目标、撤退与治疗；真实 GPU 回归在 1600×900 分辨率捕获 Godot Dummy 渲染器无法提供的可视属性。

判定策略严格：非零退出码、\texttt{FAIL:}、\texttt{ERROR:}、\texttt{SCRIPT ERROR:}、泄漏、资源未释放、非法访问或原生崩溃都会使套件失败。警告则按语义判断：故意调用不存在 Actor 方法是安全测试，应返回 \textsc{failure}；\texttt{--quit-after} 后的文件扫描中断属于预期关闭行为。

\section{视觉验证}

自动断言不能发现所有显示故障。因此视觉协议在 NVIDIA GeForce RTX 5070 Laptop GPU 和 Godot OpenGL 3.3 Compatibility 渲染器上生成稳定截图。核心截图覆盖基线、类型编码、灰度、无障碍配色、单线、紧凑、鱼眼开关、折叠、搜索、运行失败、实时黑板、Schema 编辑、Key 选择、正交连线、捆绑连线和复杂树；另外四张固定截图覆盖 121 节点练习树、可玩 241 节点树概览、平衡搜索目标和确定性的七节点游戏路径。

人工检查关注卡片重叠、端口位置、重复边、文字裁切、残留缩放、视口居中、活动路径连续性、淡化复位和小地图覆盖。正是该方法发现鱼眼虽然状态变量正确，却存在偏右中心和滚轮缩放干扰。

\section{人体实验设计}

预注册的被试内实验在可玩 241 节点树上比较 Baseline、Compact、Collapse、Fisheye、Search 和 Minimap。12 名参与者在全部六种条件下完成三类游戏开发任务：根据玩法需求定位 Action、报告七节点 \textsc{running} 路径，以及把附着 Decorator 的持续时间增加 0.10 秒。每人 18 次正式试验，共 216 次；独立的 121 节点树为每类任务提供一次不计分练习。

六组等价 Action/路径目标分别覆盖越障、垂直追击、远程压制、中距离推进、最后位置搜索和巡逻；六个编辑目标均为附着在 Action 上的真实 Decorator。方法顺序采用六种平衡序列且各分配两次；任务块顺序采用三种轮换且各分配四次。目标索引为 \((m+p)\bmod 6\)，其中 \(m\) 为方法索引，\(p\) 为参与者索引。因此每名参与者在每类任务中看到六个不同目标，而整个样本中每个方法--目标组合恰好出现两次，减少反复寻找同一张卡片带来的学习效应。

主要结果为上限 180 秒的完成时间和成功率。次要结果为误选、Zoom、Pan、总导航次数，以及七点评分的可读性与认知负荷。三类任务分别分析。连续和有序结果先使用 Friedman 检验；仅当总体检验显著时，才进行相对 Baseline 的精确配对 Wilcoxon 检验并采用 Holm 校正。成功率使用 Cochran's Q，随后进行校正的精确 McNemar 比较。报告中位数 [Q1, Q3]、配对效应量、Bootstrap 区间、排除、失败和超时；完整参与者少于八人时仅作描述统计。

参与者使用匿名编号并明确同意，可随时退出；不保存姓名和联系方式。正式招募必须遵守学校伦理和导师要求。写作时生成的工作簿包含 216 行计划数据和零条参与者观测，因此本文不报告推断性人体实验结果。

\section{有效性与可复现性}

固定资源、确定性目标、独立开关、30 次生态显示重复、平衡条件/目标顺序和集成后全回归增强了内部有效性。构念有效性仍受限制，因为面积和字段数测量的是信息密度，不是可读性本身。外部有效性限于一台 Windows 笔记本、Godot 4.6、固定生成资源和一个二维游戏。因此所有时间值都与硬件、渲染器、视口、预热和工作负载一起报告，不视为跨设备常数。

复现材料包括原始 CSV、截图、测试脚本、公式工作簿、洁净安装打包脚本和 MIT 许可证插件包。人体实验材料与自动证据分开保存，防止未采集的数据被误认为结果。
