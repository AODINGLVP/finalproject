\chapter{讨论}
\label{ch:discussion}

\section{实验平台的正确性与边界}

完整插件是显示优化实验的平台，不是单独的研究对象。它能够保存和运行行为树，也支持 Actor、复合节点、条件、动作、Decorator、黑板和实时调试。因此，实验测试的是真正能够运行的行为树，而不是只画在画布上的静态节点图。

复杂竞技场进一步确认，敌人的检测、追击、攻击、搜索和恢复由行为树选择，Actor 方法只负责移动、动画和伤害等具体效果。这说明插件适合用作实验平台，但本文不讨论行为树的基础功能是否能够帮助游戏开发。

行为树编辑器也不只是普通的树形查看器。移动同级节点可能改变执行优先级，隐藏 Decorator 可能影响调试信息，切换行为树时还必须清除之前保存的运行进度。450 项功能测试说明这些已测试场景能够正确工作，但不能证明软件在任何情况下都没有缺陷。

项目没有实现 Service 节点。现有的 Parallel、Random、Repeat、Wait、黑板和 Decorator 已经能够支持复杂演示。继续增加节点类型会增加开发和测试工作，但不能直接帮助回答本论文的显示优化问题，因此不属于当前范围。

\section{显示结果的解释}

六种显示条件解决的问题不同，不能只根据一个百分比判断哪一种最好。Baseline 显示全部信息。Compact 和 Overview 保留全部节点，但减少卡片面积和文字。Search 用于查找名称已知的节点。Focus 用于查看一个指定分支。Collapse 用于暂时收起当前不需要的分支。

在五种规模下，Overview 的卡片面积大约减少 90.3\%；364 节点树中，Search 淡化了 99.67\% 的非目标卡片；Collapse 最多减少了 96.39\% 的显示卡片。这些数字分别测量不同功能的效果，不能直接放在一起排名。

物理屏幕实验显示，当每厘米使用相同的逻辑画布大小时，31.55 英寸屏幕上的复杂树覆盖率是 15.94 英寸屏幕的 2.54 倍。这是因为大屏幕提供了更多物理显示面积，不是显示算法本身变得更快或更强。

即使使用最大的一块屏幕，241 和 364 节点树仍会达到 0.10x 的最小缩放。大屏幕能够缓解问题，但不能代替 Search、Focus 和 Collapse。Compact、Overview 和 Search 在三块屏幕上的结果比较稳定，说明这些功能不只适用于某一块屏幕。不过，这仍然不能证明用户主观上觉得它们更容易阅读。

这一结果与已有研究的观点一致。焦点与上下文方法需要在局部细节和整体结构之间作出取舍\parencite{furnas1986fisheye,lamping1995hyperbolic}。概览与细节方法能够提供整体参考，但实际效果会受到任务和切换操作影响\parencite{cockburn2008review}。本论文没有测试文献中的所有方法，只比较了 Compact、Overview、Search、Focus、Collapse 和 Baseline。

实际使用时，开发者可以根据任务选择不同功能：用 Baseline 查看完整字段，用 Compact 或 Overview 查看整体结构，用 Search 查找已知节点，再用 Focus 或 Collapse 减少无关内容。每项显示功能都可以关闭，并恢复到相同的 Baseline 状态。

Focus 和 Collapse 会保留目标节点或折叠根，帮助用户判断自己正在查看哪一部分。但是切换显示范围后，用户仍可能需要重新确认位置。相关研究把这种对原有空间位置的记忆称为“心理地图”\parencite{dogrusoz2018complexity,misue1995mentalmap}。未来的真人实验可以测试用户在多次聚焦、折叠和恢复后能否重新找到原来的节点。

\section{可靠性与发布}

检查测试日志发现了两类普通断言没有发现的问题：场景关闭后仍然存活的计时器，以及 Godot Console 退出时由命令管道引起的崩溃。项目改用节点自身状态记录时间，并让 Godot 直接写入指定日志文件。修复后，相关错误不再出现。

插件还在空白项目中进行了安装测试，确认压缩包内容、文件校验值和启用过程正确。最终图标、Godot Asset Library 介绍和跨版本兼容测试仍属于后续发布工作。

\section{有效性威胁}

\subsection{构念有效性}
卡片面积、可见比例、屏幕覆盖率、字段数和淡化数只描述界面发生了什么变化。卡片变小可能同时隐藏有用信息，其他节点被淡化后也可能更难注意。因此，61.09--61.35\% 的面积减少或 2.54 倍的覆盖率不能写成相同比例的可读性提高。要判断用户是否更容易理解，还需要真人实验。

\subsection{内部有效性}
五棵生成树使用相同规则，便于比较规模变化，但它们可能比开发者手工制作的不规则行为树更容易布局。屏幕尺寸来自 EDID，可能存在取整误差，三块屏幕的长宽比例和连接方式也不同。预热、重复测试和轮换实验顺序能够减少部分影响，但不能消除所有环境差异。

\subsection{外部有效性}
测试只使用 Godot 4.6、Windows 和当前渲染环境。物理屏幕也只有现有的三台设备，并不是随机选择的样本。因此，结果不能代表所有显示器、其他操作系统、移动设备或数千节点的行为树。可玩测试只包含一个二维战斗游戏，也没有测量不同经验开发者的长期使用情况。

\subsection{研究者与人体有效性边界}
系统和自动指标由同一名开发者设计，可能使测试更容易符合已有实现。固定生成规则、提前规定的门槛、原始数据和文件校验值可以帮助复查，但不能代替独立参与者。因此，本文结论只涉及客观显示数据，不涉及真人可用性。

\section{实践启示}

小型行为树可以直接使用 Baseline 查看完整信息。中大型行为树即使使用更大的屏幕，也可能达到 0.10x 的最小缩放。开发者可以用 Compact 或 Overview 查看整体，用 Collapse 或 Focus 编辑局部分支，用 Search 查找已知节点，最后恢复 Baseline 检查完整内容。

显示功能还必须和正常编辑功能一起测试。例如，连线不仅要显示正确，也必须能够断开；折叠不能让节点在没有提示的情况下消失；Live Debug 不能因为读取到不完整数据而清空正确状态。这些问题说明，显示优化不能脱离插件功能单独实现。
