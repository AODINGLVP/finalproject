\chapter{讨论}
\label{ch:discussion}

\section{完整系统作为研究工具}

RQ1 关注系统可行性。完成的插件表明 Godot 通用图编辑和扩展 API 足以构成接近成熟工具功能基线的行为树工作流：可序列化资源、可复用 Actor 组件、有序复合节点、条件、动作、Decorator、黑板和实时执行检查。复杂竞技场是关键证据，因为只会正确画图的系统仍可能与智能体行为无关；当前检测、追击、方向攻击、搜索和恢复由资源在运行时选择，而 Actor 方法只提供物理效果。

功能广度也说明行为树编辑器不只是普通树查看器：移动同级节点会改变优先级，隐藏 Decorator 会遮蔽失败原因，切换树必须清除执行记忆，图在被检查时仍持续更新。资源、Runner 和编辑器分层降低了耦合，但集成面仍很大。因此 447 条核心断言应被视为对指定场景的证据，而不是不存在任何缺陷的证明。

不实现 Service 节点是合理范围决策。Parallel、Random、Repeat、Wait、类型化黑板和 Decorator 已能支撑复杂演示。增加另一种仿 UE 抽象会扩大运行时和编辑器组合，却不能直接回答主要研究问题。毕业项目应优先保持可辩护、经过测试的边界。

\section{显示结果的解释}

不同显示技术面向不同任务，其百分比不是统一效用分数。Collapse 的 99.5\% 可见节点降低适合已知哪些子树可抽象的情况，却会移除拓扑并可能隐藏意外运行分支；Fisheye 的 20\% 数值较小，但保留完整结构，可能更适合导航中局部阅读；Search 的 99.7\% 淡化适合已知文字目标，却无法帮助不知道名称的用户；Minimap 的 100\% 覆盖提供方向感而不是细节。

可玩 241 节点结果降低了几何发现只是某一种合成生成器产物的风险。其分支对应游戏开发者实际会修改的行为，例如投射物攻击、跳跃与梯子通行、搜索和巡逻，并包含 39 个会扩大真实卡片的附着 Decorator。Compact 和 Overview 仍分别把卡片面积降低 57.93\% 和 89.48\%，Focus 和 Collapse 则在零重叠下显示 32 和 43 张卡片。这证明显示机制可应用于有游戏意义的资源，而不是证明生态场景中的可用性已经改善。例如 32 张卡片的聚焦视图可能加速已知巡逻子系统的工作，却也可能妨碍发现更高优先级的远程攻击分支。

相同 240 步拖拽路径上的 26.60\% 降低比运行 Tick 性能更直接关联编写工作，因为它测量的是开发者在编辑器中移动卡片的操作。然而，毫秒降低不一定能被用户感知，单机五轮测试也不能决定满意度。合理解释是：延迟资源通知和快照复制确实减少了重复处理，同时保持最终位置与撤销；实际感知仍留给参与者实验。

这种任务依赖性与文献一致。焦点+上下文平衡局部和全局\parencite{furnas1986fisheye,lamping1995hyperbolic}，概览+细节提供稳定全局参考但会分散注意\parencite{cockburn2008review}；多列布局的优势针对大扇出浏览\parencite{song2010largefanout}，不能推出所有行为树都应重排；Quilts 的路径任务结果\parencite{bae2011quilts}支持补充路径摘要，而不是完全替换可编辑节点图。

因此最重要的设计结果不是找到唯一“最佳方法”，而是受控组合。设计者可以用 Compact 增加密度，用 Minimap 保持概览，用 Search 定位，再用语义细节检查；运行时则用 Branch Dimming 与文字路径。独立开关也便于隔离故障，例如鱼眼残留 Transform 时可以单独关闭而不影响折叠和实时调试。

心理地图只得到部分处理。Stable Layout 和中心补偿鱼眼减少无关移动，折叠保留 Owner 与摘要；但新子树与已有位置冲突时，自动布局仍可能移动节点。相关研究强调空间连续性\parencite{dogrusoz2018complexity,misue1995mentalmap}。未来应测量用户多次折叠/展开后重访节点的能力，而不只统计重叠。

\section{Live Debug 作为可读性机制}

运行检查把大树问题从一般拓扑阅读变成时序解释。Path Summary、Active Edge、Inactive Dimming、Failure Annotation 和 Live Blackboard 提供冗余证据：颜色表达位置，文字表达顺序，黑板表达决策输入。对于 Decorator 尤其重要，因为失败可以附在 Owner 上，而不是从从未执行的子节点猜测。

原子快照是编辑器和游戏分进程运行下的工程折中。它简单且可检查，但文件轮询不适合高频历史或远程目标，也只保留最新合并状态。Socket 或 Godot Debugger 协议可支持事件时间线和远程 Actor，但同步复杂度更高；对当前项目而言，稳健的最新状态比完整历史更合理。

\section{缓存权衡}

性能实验在固定工作负载下肯定回答 RQ3。索引查询替代递归执行中的重复线性扫描，因此树越大收益越高。精确签名避免了常见错误：把资源身份和节点数相同误认为拓扑未变；测试证明节点数不变的结构修改也能正确失效。

缓存并非免费。每次外部 Tick 都有 \(O(n)\) 签名扫描，所以 31 节点收益只有 15.98--26.46\%，明显低于 364 节点。事件驱动版本号可以达到 \(O(1)\) 校验，但前提是所有修改入口都可靠递增；Godot Resource 可以直接编辑，仅靠版本号会降低安全性。未来可在编辑器变更信号和周期性精确校验之间采用混合方案。

基准还包含 GDScript 和测试框架开销，且只运行在一台 Windows 笔记本。Runner 数条件固定总工作量，因此不是 50 个生产智能体持续 Tick 的精确帧成本。结果只证明控制配对下的相对效果。

\section{可靠性与发布}

严格日志策略发现了断言可能漏掉的问题，包括异步 Timer 在场景退出后存活，以及 PowerShell 原生管道触发 Godot Console 退出期崩溃。改用节点本地状态机消除生命周期泄漏，直接启动 Godot 并指定绝对日志路径避开管道问题。调试插件本身不能制造误导错误，因此这些修复具有实际意义。

洁净安装测试验证 ZIP 边界、清单哈希和空项目启用，而不只是检查文件存在。剩余发布工作包括最终图标、Asset Library 描述和明确目标版本后的兼容矩阵。

\section{有效性威胁}

\subsection{构念有效性}
卡片面积、可见比例、字段数和淡化数测量的是表示属性，不是理解。更小的视图可能隐藏任务所需信息，更强的淡化可能降低对备选项的察觉。因此不能把可玩树 57.93\% 的面积降低写成 57.93\% 的可读性提高，必须通过参与者实验验证。

\subsection{内部有效性}
生成树结构一致有利于比较，却可能比不规则人工树更容易搜索和布局。可玩 241 节点资源加入了具有意义的不规则内容，但仍只是一个人工工作负载。显示时间会受操作系统调度、GPU/编辑器预热和温度状态影响；三次预热、30 次重复、循环序位、中位数、四分位数和第 95 百分位能减少但不能消除噪声。固定截图也不能覆盖所有开关组合。

\subsection{外部有效性}
测试限于 Godot 4.6、Windows 和一台 NVIDIA GPU。Godot 内部 GraphEdit 层可能跨版本改变，尤其单线模式会隐藏原生子层。结果不能直接推广到移动编辑器、不同 DPI 或数千节点树。具有行为意义的工作负载仍只是一个二维战斗游戏，而参与者样本尚未招募，因此不同开发者经验水平与其他游戏类型上的迁移仍未测量。

\subsection{研究者与参与者有效性}
开发者同时设计系统和自动指标，可能使测试偏向已有机制。公开原始数据和边界有助于审计，但仍需要独立参与者。修订后的设计不再让所有条件反复使用一个已记住的目标：六条等价路径和六个 Decorator 目标经过平衡，使每个方法--目标组合在 12 名参与者中出现两次。这控制了一种学习威胁，却不能消除研究者提示或招募偏差；标准化说明、匿名编号和冻结的排除规则用于降低这些风险。当前没有参与者数据，因此没有人类可用性结论的实证依据。

\section{实践启示}

小树适合完整细节节点图；中大型树应按任务提供工具，而不是强制单一自适应模式：Compact/Semantic 用于概览，Collapse/Focus 用于子系统编辑，Search 用于已知目标，Minimap 用于方向，Active Path/Failure 用于诊断。稳定几何应作为安全默认，强畸变功能应可选且易于复位。

对插件开发而言，显示创新必须和编写语义一起测试：连线即使好看，不能点击断开就不完整；折叠若允许新节点无摘要地隐藏就不完整；Live Debug 若因半条消息清空正确状态就不安全。因此集成测试本身也是贡献的一部分。
