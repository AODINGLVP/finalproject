# 241 节点可玩行为树显示实验结果

## 状态与环境

本结果来自 Godot 4.6 stable、OpenGL Compatibility renderer、NVIDIA GeForce RTX 5070 Laptop GPU 和固定 1600×900 SubViewport。测试对象为实际驱动复杂竞技场敌人的 `complex_display_tree_241.tres`，包含 241 个资源节点、202 张画布卡片和 39 个附加 Decorator。

六个显示条件各预热 3 次、正式测量 30 次，共 180 条原始观测。条件顺序按轮次循环换序，使每个条件在六个顺序位置各出现 5 次。运行以退出码 0 完成，所有预设断言通过。

数据源：

- `testgame/testgame/test_results/complex_display_experiment_raw.csv`
- `testgame/testgame/test_results/complex_display_experiment_summary.csv`
- `testgame/testgame/test_results/drag_performance_comparison.csv`

Compact 没有隐藏节点，而是将总卡片面积降低 57.93%。Semantic Zoom 总览仍保留全部 202 张卡片，但将卡片面积降低 89.48%。Search 将 201/202 张卡片弱化，只保留一个目标匹配；Subtree Focus 和 Context Collapse 分别将画布范围限制为 32 和 43 张卡片。所有条件均为 0 卡片重叠，且实验结束后资源节点位置未改变。

这些结果证明显示开关按设计改变了复杂树的视觉密度和上下文范围，并且不会因缩小而把节点叠在一起。它们不证明真人更容易理解、定位或编辑；该结论必须由预注册的开发任务实验提供。

## 操作响应记录

六种条件的 30 次操作时间均报告 Median [Q1, Q3] 和 P95，但各条件执行的动作不同（完整重建、样式切换、搜索或子树重建），因此不应按数值大小直接排列方法优劣。最高的 P95 为 Baseline 完整重建的 932.64 ms；其余五种条件的 P95 为 327.51–534.02 ms。该结果仅说明本机实验过程中操作在约一秒内完成，不是可用性主要结果。

固定 240 步节点拖拽的同任务前后对照中，中位总时间由 1,124.693 ms 降为 825.571 ms，即降低 26.60%；每步由 4.686 ms 降为 3.440 ms。此数据支持“大图拖拽处理时间下降”，但是否被用户感知为更流畅仍需真人任务数据。

## 论文可直接使用的客观结果段

在 241 节点可玩敌人行为树上进行了真实 GPU 辅助实验。该资源包含 202 张画布卡片和 39 个附加 Decorator，六个显示条件分别经过 3 次预热和 30 次正式重复，共获得 180 条观测。与 Baseline 相比，Compact Cards 在不隐藏节点的情况下将总卡片面积降低 57.93%，Compact 与 Semantic Zoom 组合将其降低 89.48%；Search 弱化 201/202 张卡片，Subtree Focus 和 Context Collapse 则分别把当前画布限制为 32 和 43 张卡片。所有条件均未产生节点卡片重叠，也没有修改资源中保存的节点位置。因此，客观结果表明这些机制能够在保持树结构完整的同时改变大图的视觉密度与上下文范围。不过，面积或可见节点的减少并不能自动证明游戏开发者的理解和编辑表现得到改善，后续结论需依据预注册的定位、路径追踪和 Decorator 编辑人工实验。

## 限制

- 数据来自一台 Windows 笔记本和一个 Godot 版本，操作时间不能外推到其他硬件。
- 六个条件的操作语义不同，因此时间列只用于响应范围，不作条件间性能排名。
- 几何指标衡量“呈现发生了什么”，不衡量“人是否更方便”。
- 真人实验尚未采集参与者数据，当前不能报告可读性、认知负担或任务时间改善。
