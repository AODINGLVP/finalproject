# 物理屏幕尺寸实验预注册方案

## 研究问题

在保持节点逻辑尺寸和树结构不变时，物理屏幕可用面积增加会怎样改变复杂行为树的可见覆盖、Fit-to-view 缩放和目标定位？现有 Compact、Overview、Search、Focus 与 Collapse 是否能在不同物理尺寸下保持其几何作用和结构安全？

## 自变量

1. EDID 报告的屏幕物理宽度、高度、对角线和面积。
2. 行为树资源节点数：31、61、121、241、364。
3. 显示条件：Baseline、Compact Cards、Optimized Overview、Optimized Search、Subtree Focus、Context Collapse。

原生分辨率、刷新率、Windows 缩放和 GPU 连接只作为设备审计信息保存，不作为主要解释变量，也不进行性能排名。

## 尺寸归一化

每块屏幕使用相同的 35 逻辑单位/厘米。归一化画布宽高分别为：

```text
canvas_width  = EDID_width_cm  × 35
canvas_height = EDID_height_cm × 35
```

因此节点卡片的逻辑尺寸保持不变，而画布随物理表面积增长。这个处理用于隔离“物理显示面积”因素，避免把不同像素密度直接解释成屏幕尺寸效果。

## 固定因素

- 同一台电脑、同一 Godot 4.6 可执行文件、同一插件提交。
- 同一确定性树生成器、节点位置、目标节点和条件顺序。
- 真实 GPU `gl_compatibility` 渲染，不使用 headless/Dummy 截图。
- 每个设备先预热两次，再正式重复三次。
- 每次条件结束后验证节点资源位置和从左到右执行顺序未改变。

三块屏幕共形成 `3 × 5 × 6 × 3 = 270` 条正式观测。每块屏幕另外保存 241、364 节点在 Baseline、Optimized Overview 和 Optimized Search 下的六张证据截图，共十八张。

## 主要指标

- 条件应用后、Fit 前进入画布的卡片中心数量与比例。
- Fit-to-view 后进入画布的卡片中心数量与比例。
- Fit-to-view 缩放值。
- 图边界面积相对物理屏幕面积的倍数。
- 卡片总面积（换算为平方厘米）和相对 Baseline 的降低比例。
- Search 目标是否进入视口，以及目标到视口中心的归一化距离。
- Focus/Collapse 相对 Baseline 的上下文卡片降低比例。
- 节点重叠对数与最小父子间距。
- 保存位置与执行顺序签名是否保持。

## 预设安全与效果检查

1. 所有屏幕、规模和条件均为零卡片重叠，父子间距非负。
2. 所有运行均保持资源位置与执行顺序。
3. Search 一次提交后目标必须位于画布内。
4. Compact 卡片面积相对 Baseline 至少降低 40%。
5. Overview 卡片面积相对 Baseline 至少降低 70%。
6. 121 节点以上，Focus 和 Collapse 的当前上下文至少降低 70%。

## 分析规则

- 同一棵树、同一条件在不同屏幕上配对比较。
- 几何指标报告确定值、三次重复一致性和相对 Baseline 的变化。
- 主要屏幕尺寸趋势按 EDID 物理面积和对角线排序。
- 条件处理时间只用于检查运行稳定性；不同屏幕连接到不同 GPU 时不得把时间差解释为屏幕尺寸效果。
- 分辨率数据仅放入设备表和可复现清单，不作为图表横轴或论文主结论。

## 允许与禁止的结论

允许说明物理尺寸归一化画布下，可见覆盖、缩放、上下文和目标定位如何变化。允许说明显示机制在三块实际连接的屏幕上是否保持零重叠和结构安全。

没有真人参与，因此禁止把几何覆盖直接写成“人更容易看懂”“任务完成更快”或“认知负荷下降”。本实验也不能把三台具体设备外推为所有显示器。
