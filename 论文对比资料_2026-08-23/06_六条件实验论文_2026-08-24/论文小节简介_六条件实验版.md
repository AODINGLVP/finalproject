# 论文小节简介（六条件实验版）

## 前置部分

- 致谢：留给作者最后填写。
- 声明：说明论文、软件和数据归属，并提醒最终提交前如实说明生成式 AI 的使用。
- 摘要：用一页以内说明研究问题、六种条件、节点规模、物理屏幕实验、主要数据和结论边界。

## 第 1 章 引言

- 1.1 研究背景：解释行为树为什么适合游戏 AI，以及大型节点图为什么会变得难以检查。
- 1.2 问题定义与研究空白：介绍已有树可视化思路，并指出这些研究没有直接给出可执行 Godot 行为树编辑器中的组合方案。
- 1.3 研究目标与问题：给出论文唯一的研究问题，关注不同节点数量、物理屏幕尺寸和优化前后差异。
- 1.4 研究目标与成功标准：区分“插件基础功能必须正确”和“显示优化需要通过实验回答”两类工作，并用直白语言说明通过与失败标准。

## 第 2 章 文献综述

- 2.1 作为可执行层级的行为树：说明行为树节点语义、运行记忆、黑板和 Decorator 为什么会影响编辑器显示。
- 2.2 节点--连线树与扩展性：讨论传统节点图在大型树上的空间问题，以及布局不能改变执行顺序。
- 2.3 焦点、上下文与概览：回顾焦点、概览和语义缩放等相关思路，为六种实验条件提供理论背景；这里是文献讨论，不代表都进入实验。
- 2.4 复杂度管理与心理地图：说明折叠、聚焦和搜索怎样减少当前上下文，以及它们可能隐藏信息的代价。
- 2.5 运行时解释与失败定位：说明动态状态和 Decorator 失败为什么让行为树比普通层级图更复杂。
- 2.6 研究空白与设计启示：总结文献对本项目的约束，并强调几何数据不能直接等同于真人可读性。

## 第 3 章 研究方法

- 3.1 研究策略：说明采用设计科学与软件工程结合的方法，插件是研究产物，实验数据用于回答研究问题。
- 3.2 实验因素与数据集：先用表格逐项解释六种条件具体开启什么、界面发生什么、实验测量什么；再说明 31、61、121、241、364 节点树和可玩 241 节点树。
- 3.3 受控多规模显示与拖拽实验：说明真实 GPU、预热、重复次数、条件顺序和版本化拖拽对照。
- 3.4 物理屏幕尺寸实验：比较三块屏幕的物理尺寸；分辨率只作记录，不作为研究变量。
- 3.5 可玩树生态显示校验：在真正控制复杂敌人的 241 节点树上重复六种条件，检查生成树结果能否迁移到有游戏意义的资源。
- 3.6 正确性与集成评估：确认节点执行、保存重载、撤销重做和游戏行为正确，保证实验平台可信。
- 3.7 视觉验证：用真实渲染画面检查重叠、裁切、搜索居中、聚焦/折叠范围和返回 Baseline 后的复位。
- 3.8 有效性与可复现性：说明固定资源、原始 CSV、截图和哈希如何支持复现，同时列出硬件和样本限制。

## 六种实验条件怎么操作

1. Baseline：展开全部节点，清空搜索与聚焦，缩放恢复到 100%，关闭本实验优化，显示完整卡片和全部分支。
2. Compact Cards：只开启 Compact；所有节点仍显示，但卡片只保留类型标识和短标题。
3. Optimized Overview：开启 Compact 与 Semantic Zoom，把画布缩放到 50%，用低细节卡片查看整体结构。
4. Optimized Search：在 Overview 基础上搜索预先固定且唯一的节点标题；目标进入视口并保持显著，其他卡片淡化。
5. Subtree Focus：开启 Compact，把预先固定分支设为 Focus Root，只显示该分支及必要上下文。
6. Context Collapse：开启 Compact，保留通向固定目标的路径，折叠路径外的指定分支；折叠根和摘要保留，后代卡片隐藏。

- 4.1 架构与项目边界：说明插件资源、运行时、编辑器和游戏之间的职责。

- 4.3 运行时语义：说明各节点返回 success、failure 或 running 的规则，以及同级顺序为什么必须保持。
- 4.4 编辑器编写工作流：说明右键创建、连线、拖拽、类型化编辑、保存、撤销和重做。
- 4.5 Live Debug 与黑板检查：作为平台功能说明怎样检查运行状态，不把它当作显示实验条件。
- 4.6 大型树显示机制：只解释六种条件实际依赖的 Compact、Semantic Zoom、Search、Focus 和 Collapse 机制及安全复位。
- 4.6.1 信息密度控制：说明 Compact Cards 和 Optimized Overview。
- 4.6.2 目标定位与上下文控制：说明 Optimized Search、Subtree Focus 和 Context Collapse。
- 4.7 物理屏幕实验基础设施：说明怎样读取物理尺寸、保持每厘米逻辑密度，并追加新屏幕 Session。
- 4.8 演示游戏：说明复杂敌人的近战、远程、跳跃、攀爬、搜索、撤退和恢复如何由 241 节点行为树选择。

## 第 5 章 结果与分析

- 5.1 功能正确性：报告自动测试和复杂游戏验证，证明平台可用于实验。
- 5.2 受控多规模显示结果：比较五种节点规模下六种条件的卡片面积、可见上下文、搜索淡化、Fit-to-view 和重叠。
- 5.3 物理屏幕尺寸结果：报告三块屏幕上 241 与 364 节点树的覆盖率，并说明大屏幕仍无法消除大型树问题。
- 5.4 版本化拖拽交互结果：比较优化前后固定拖拽路径处理时间；大树改善明显，小树没有稳定改善。
- 5.5 可玩 241 节点树显示结果：说明六种条件在真正控制敌人的树上产生的面积、卡片数和上下文变化。
- 5.6 视觉回归发现：记录搜索居中、节点重叠和条件复位等数值测试不容易发现的问题，并给出紧凑、折叠、搜索图例。
- 5.7 对应研究问题的结果：直接回答唯一研究问题，同时说明结果只支持可测显示与交互属性，不证明真人理解。

## 第 6 章 讨论

- 6.1 实验平台的正确性与边界：说明插件基础能力是研究前提，不是论文要证明的对象。
- 6.2 显示结果的解释：解释六种条件分别适合整体查看、已知目标定位或局部分支编辑，不能用一个百分比排出绝对最好。
- 6.3 可靠性与发布：说明严格日志和洁净安装怎样避免“断言通过但程序实际出错”。
- 6.4 有效性威胁：分别讨论指标、实验顺序、硬件、树样本和研究者偏差。
- 6.4.1 构念有效性：面积和覆盖率不是人的理解能力。
- 6.4.2 内部有效性：时间会受预热、调度和实验顺序影响。
- 6.4.3 外部有效性：结果目前只覆盖 Godot 4.6、一台电脑、三块屏幕和有限树规模。
- 6.4.4 研究者与人体有效性边界：没有真人参与者数据，因此不能声称认知负荷或长期效率改善。
- 6.5 实践启示：建议小树使用 Baseline，中大型树按任务使用 Compact/Overview、Search、Focus 或 Collapse，并随时恢复 Baseline 检查完整结构。

## 第 7 章 结论

- 7.1 总结：汇总平台、六种条件、节点规模、屏幕实验和拖拽实验的主要发现。
- 7.2 贡献：概括可执行插件、六种定义明确的实验条件和可复现数据包。
- 7.3 局限：说明当前硬件、屏幕、树规模和缺少真人数据的限制。
- 7.4 未来工作：继续追加新屏幕和不规则树；若以后有条件，可用同样六种条件做真人任务实验。
- 7.5 最终结论：用一段话回答研究问题，不扩大到没有数据支持的结论。
