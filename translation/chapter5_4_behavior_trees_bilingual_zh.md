## 5.4 Behavior Trees / 5.4 行为树

| English | 中文翻译 |
| --- | --- |
| Behavior trees have become a popular tool for creating AI characters. Halo 2 [92] was one of the first high-profile games for which the use of behavior trees was described in detail and since then many more games have followed suit. | 行为树已经成为创建 AI 角色的一种流行工具。《Halo 2》[92] 是最早被详细介绍其行为树用法的知名游戏之一，此后许多游戏也陆续采用了这种技术。 |
| They are a synthesis of a number of techniques that have been around in AI for a while: Hierarchical State Machines, Scheduling, Planning, and Action Execution. Their strength comes from their ability to interleave these concerns in a way that is easy to understand and easy for non-programmers to create. Despite their growing ubiquity, however, there are things that are difficult to do well in behavior trees, and they aren't always a good solution for decision making. | 行为树综合了 AI 领域中已经存在一段时间的多种技术：层次状态机、调度、规划以及动作执行。它的优势在于能够把这些关注点交织在一起，同时保持结构容易理解，也便于非程序员创建。不过，尽管行为树越来越常见，仍然有一些事情很难用行为树做好；它也并不总是决策问题的最佳方案。 |
| Behavior trees have a lot in common with Hierarchical State Machines but, instead of a state, the main building block of a behavior tree is a task. A task can be something as simple as looking up the value of a variable in the game state, or executing an animation. | 行为树和层次状态机有许多共同点，但行为树的主要构成单元不是“状态”，而是“任务”。一个任务可以很简单，例如查询游戏状态中某个变量的值，也可以是执行一段动画。 |
| Tasks are composed into sub-trees to represent more complex actions. In turn, these complex actions can again be composed into higher level behaviors. It is this composability that gives behavior trees their power. Because all tasks have a common interface and are largely self-contained, they can be easily built up into hierarchies, i.e. behavior trees, without having to worry about the details of how each sub-task in the hierarchy is implemented. | 任务可以组合成子树，用来表示更复杂的动作；这些复杂动作又可以继续组合成更高层次的行为。正是这种可组合性赋予了行为树强大的表达能力。由于所有任务都具有统一接口，并且基本上是自包含的，因此它们可以很容易地组织成层次结构，也就是行为树，而不必关心层次中每个子任务的具体实现细节。 |

## Types of Task / 任务类型

| English | 中文翻译 |
| --- | --- |
| Tasks in a behavior tree all have the same basic structure. They are given some CPU time to do their thing, and when they are ready they return with a status code indicating either success or failure. Some developers use a larger set of return values, including an error status, when something unexpected went wrong, or a need more time status for integration with a scheduling system. | 行为树中的任务都具有相同的基本结构。系统会分配给它们一些 CPU 时间来执行自己的工作；当任务准备好返回时，它会返回一个状态码，表示成功或失败。有些开发者会使用更多种返回值，例如发生意外情况时返回错误状态，或者为了与调度系统集成而返回“需要更多时间”的状态。 |
| While tasks of all kinds can contain arbitrarily complex code, the most flexibility is provided if each task can be broken into the smallest parts that can usefully be composed. This is especially so because, while powerful just as a programming idiom, behavior trees really shine when coupled with a graphical user interface (GUI) to edit the trees. That way, designers, technical artists and level designers can potentially author complex AI behavior. | 虽然各种任务内部都可以包含任意复杂的代码，但如果能把每个任务拆分成仍然有组合价值的最小部分，就能获得最大的灵活性。这一点尤其重要，因为行为树作为一种编程范式已经很强大，但当它与用于编辑树结构的图形界面结合时，才真正展现出优势。这样一来，设计师、技术美术和关卡设计师都有可能创作复杂的 AI 行为。 |
| At this stage, our simple behavior trees will consist of three kinds of tasks: Conditions, Actions, and Composites. | 在这一阶段，我们讨论的简单行为树由三类任务组成：条件、动作和组合节点。 |
| Conditions test some property of the game. There can be tests for proximity, tests for line of sight, tests on the state of the character, and so on. Each of these kinds of tests needs to be implemented as a separate task, usually with some parameterization so they can be easily reused. Each Condition returns the success status code if the Condition is met and returns failure otherwise. | 条件用于测试游戏中的某些属性。例如可以测试距离，判断角色是否在敌人一定范围内；可以测试视线；也可以测试角色状态，例如生命值是否充足、是否有弹药等。每一种测试通常都需要实现成单独的任务，并带有一定参数化能力，以便复用。当条件满足时，条件节点返回成功状态；否则返回失败。 |
| Actions alter the state of the game. There can be Actions for animation, for character movement, to change the internal state of the character, to play audio samples, to engage the player in dialog, and to engage specialized AI code such as pathfinding. Just like Conditions, each Action will need to have its own implementation, and there may be a large number of them in your engine. | 动作用于改变游戏状态。动作可以用于播放动画、控制角色移动、改变角色内部状态，例如休息会恢复生命值、播放音频、与玩家进行对话，或者调用专门的 AI 代码，例如寻路。和条件一样，每个动作都需要自己的具体实现，因此在一个引擎中可能会存在大量动作节点。 |
| Most of the time Actions will succeed. If there's a chance they might not, it is better to use Conditions to check for that before the character starts trying to act. It is possible to write Actions that fail if they can't complete, however. | 大多数时候，动作都会成功。如果某个动作存在失败的可能，通常更好的做法是在角色开始尝试执行动作之前，先用条件节点进行检查。当然，也可以编写那种在无法完成时返回失败的动作节点。 |
| If Conditions and Actions seem familiar from our previous discussion on decision trees and state machines, they should. They occupy a similar role in each technique. The key difference in behavior trees, however, is the use of a single common interface for all tasks. | 如果你觉得条件和动作很像前面讨论过的决策树和状态机中的内容，这是正常的。它们在这些技术中扮演的角色确实相似。不过，行为树的关键区别在于所有任务都使用统一的通用接口。 |
| This means that arbitrary Conditions, Actions, and groups can be combined together without any of them needing to know what else is in the behavior tree. | 这意味着任意条件、动作以及分组结构都可以组合在一起，而它们彼此不需要知道行为树中还存在什么其他内容。 |
| Both Conditions and Actions sit at the leaf nodes of the tree. Most of the branches are made up of Composite nodes. As the name suggests, these keep track of a collection of child tasks, and their behavior is based on the behavior of their children. | 条件和动作都位于树的叶子节点。树的大多数分支则由组合节点构成。顾名思义，组合节点会管理一组子任务，而它自身的行为取决于这些子任务的行为。 |
| Unlike Actions and Conditions, there are normally only a handful of Composite tasks because with only a handful of different grouping behaviors we can build very sophisticated behaviors. | 与动作和条件不同，组合任务通常只有少数几种，因为只需要少量不同的分组行为，就可以构建出非常复杂的行为。 |
| For our simple behavior tree we'll consider two types of Composite tasks: Selector and Sequence. Both of these run each of their child behaviors in turn. When a child behavior is complete and returns its status code the Composite decides whether to continue through its children or whether to stop there and then and return a value. | 对于这里的简单行为树，我们先考虑两种组合任务：选择器和序列。二者都会依次运行各自的子行为。当某个子行为完成并返回状态码后，组合节点会决定是继续执行后面的子节点，还是立即停止并返回一个值。 |
| A Selector will return immediately with a success status code when one of its children runs successfully. As long as its children are failing, it will keep on trying. If it runs out of children completely, it will return a failure status code. | 选择器在任意一个子节点成功运行时，会立即返回成功状态。只要子节点不断失败，它就会继续尝试下一个子节点。如果所有子节点都尝试完仍没有成功，它就返回失败状态。 |
| A Sequence will return immediately with a failure status code when one of its children fails. As long as its children are succeeding, it will keep going. If it runs out of children, it will return in success. | 序列节点在任意一个子节点失败时，会立即返回失败状态。只要子节点一直成功，它就继续执行下一个子节点。如果所有子节点都执行完并且都成功，它就返回成功。 |
| Selectors are used to choose the first of a set of possible actions that is successful. A Selector might represent a character wanting to reach safety. There may be multiple ways to do that, such as taking cover, leaving a dangerous area, or calling for backup. | 选择器用于在一组可能的动作中选择第一个成功的动作。例如，一个选择器可以表示角色想要抵达安全位置。实现这一目标可能有多种方式，例如寻找掩体、离开危险区域，或者呼叫支援。 |
| The Selector will first try to take cover; if that fails, it will leave the area. If that succeeds, it will stop - there's no point also calling for backup, as we've solved the character's goal of reaching safety. If we exhaust all options without success, then the Selector itself has failed. | 选择器会先尝试寻找掩体；如果失败，就尝试离开该区域。如果离开成功，它就停止执行，因为角色“抵达安全位置”的目标已经解决，没有必要再呼叫支援。如果所有选项都尝试完仍未成功，那么选择器本身就失败了。 |
| A Selector task is depicted graphically in Figure 5.22. First the Selector tries a task representing attacking the player; if it succeeds, it is done. If the attack task fails, the Selector node will go on to try a taunting animation instead. As a final fall back, if all else fails, the character can just stare menacingly. | 图 5.22 以图形方式展示了一个选择器任务。选择器首先尝试表示攻击玩家的任务；如果成功，就结束。如果攻击任务失败，选择器节点会继续尝试播放嘲讽动画。作为最后的退路，如果其他事情都失败了，角色就只能恶狠狠地盯着玩家。 |
| Sequences represent a series of tasks that need to be undertaken. Each of our reaching-safety actions in the previous example may consist of a Sequence. To find cover we'll need to choose a cover point, move to it, and, when we're in range, play a roll animation to arrive behind it. | 序列表示一组需要依次完成的任务。前面例子中每一种“抵达安全位置”的动作，都可以由一个序列构成。为了寻找掩体，我们需要先选择一个掩体点，然后移动过去，并在进入合适范围后播放翻滚动画，使角色到达掩体后方。 |
| If any of the steps in the sequence fails, then the whole sequence has failed: if we can't reach our desired cover point, then we haven't reached safety. Only if all the tasks in the Sequence are successful can we consider the Sequence as a whole to be successful. | 如果序列中的任意一步失败，那么整个序列就失败了：如果我们无法到达目标掩体点，就不能算已经抵达安全位置。只有当序列中的所有任务都成功时，整个序列才能被认为成功。 |
| Figure 5.23 shows a simple example of using a Sequence node. In this behavior tree the first child task is a condition that checks if there is a visible enemy. If the first child task fails, then the Sequence task will also immediately fail. | 图 5.23 展示了一个使用序列节点的简单例子。在这棵行为树中，第一个子任务是一个条件，用来检查是否存在可见敌人。如果第一个子任务失败，那么序列任务也会立即失败。 |
| If the first child task succeeds then we know there is a visible enemy, and the Sequence task goes on to execute the next child task, which is to turn away, followed by the running task. The Sequence task will then terminate successfully. | 如果第一个子任务成功，那么我们就知道存在可见敌人；随后序列任务会继续执行下一个子任务，即转身，然后再执行逃跑任务。之后，整个序列任务会以成功状态结束。 |

## A Simple Example / 一个简单示例

| English | 中文翻译 |
| --- | --- |
| We can use the tasks in the previous example to build a simple but powerful behavior tree. The behavior tree in this example represents an enemy character trying to enter the room in which the player is standing. | 我们可以使用前面例子中的任务构建一棵简单但功能强大的行为树。这个例子中的行为树表示一个敌方角色试图进入玩家所在的房间。 |
| I will build up the tree in stages, to emphasize how the tree can be created and extended incrementally. This process of refining the behavior tree is part of its attraction, as simple behaviors can be roughed in and then refined in response to play testing and additional development resources. | 我会分阶段构建这棵树，以强调行为树可以如何逐步创建和扩展。逐步细化行为树的过程正是它的吸引力之一：我们可以先粗略搭出简单行为，然后根据试玩反馈和后续开发资源不断完善。 |
| Our first stage, Figure 5.24, shows a behavior tree made up of a single task. It is a move action, to be carried out using whatever steering system our engine provides. | 第一阶段如图 5.24 所示，这棵行为树只由一个任务构成。它是一个移动动作，可以使用引擎提供的任意操控或转向系统来执行。 |
| To run this task we give it CPU time, and it moves into the room. This was state-of-the-art AI for entering rooms before Half-Life, of course, but wouldn't go down well in a shooter now! The simple example does make a point, however. When you're developing your AI using behavior trees, just a single naive behavior is all you need to get something working. | 为了运行这个任务，我们给它分配 CPU 时间，它就会移动进入房间。当然，在《Half-Life》之前，这也许算得上“进入房间”的先进 AI；但放在今天的射击游戏里就不太够看了。不过，这个简单例子确实说明了一个要点：当你使用行为树开发 AI 时，只需要一个非常朴素的行为，就足以先让系统跑起来。 |
| In our case, the enemy is too stupid: the player can simply close the door and confound the incoming enemy. | 在这个例子中，敌人太笨了：玩家只要关上门，就能让正在进入房间的敌人不知所措。 |
| So, we'll need to make the tree a little more complex. In Figure 5.25, the behavior tree is made up of a Selector, which has two different things it can try, each of which is a Sequence. | 因此，我们需要让这棵树稍微复杂一些。在图 5.25 中，行为树由一个选择器构成，它有两个可以尝试的分支，而每个分支都是一个序列。 |
| In the first case, it checks to see if the door is open, using a Condition task; then it moves into the room. In the second case, it moves to the door, plays an animation, opens the door, and then moves into the room. | 第一种情况中，它使用条件任务检查门是否打开；如果门开着，就进入房间。第二种情况中，它先移动到门前，播放一段动画，打开门，然后再进入房间。 |
| Let's think about how this behavior tree is run. Imagine the door is open. When it is given CPU time, the Selector tries its first child. That child is made up of the Sequence task for moving through the open door. | 让我们思考一下这棵行为树是如何运行的。假设门是开着的。当行为树获得 CPU 时间时，选择器会尝试它的第一个子节点。这个子节点是一个序列任务，用于穿过已经打开的门。 |
| The Condition checks if the door is open. It is, so it returns success. So, the Sequence task moves on to its next child - moving through the door. This, like most actions, always succeeds, so the whole of the Sequence has been successful. | 条件节点检查门是否打开。门确实开着，因此它返回成功。于是，序列任务继续执行下一个子节点，也就是穿过门。这个动作和大多数动作一样，总是成功，因此整个序列成功。 |
| Back at the top level, the Selector has received a success status code from the first child it tried, so it doesn't bother trying its other child: it immediately returns in success. | 回到顶层，选择器从第一个尝试的子节点那里收到了成功状态码，因此它不会再去尝试另一个子节点，而是立即返回成功。 |
| What happens when the door is closed? As before the Selector tries its first child. That Sequence tries the Condition. This time, however, the Condition task fails. The Sequence doesn't bother continuing; one failure is enough, so it returns in failure. | 当门是关着的时候会发生什么？和前面一样，选择器会先尝试它的第一个子节点。这个序列会尝试其中的条件节点。不过这一次，条件任务失败了。序列不再继续执行；一次失败已经足够，所以它返回失败。 |
| At the top level, the Selector isn't fazed by a failure; it just moves onto its next child. So, the character moves to the door, opens it, then enters. | 在顶层，选择器并不会因为失败而停止；它只是继续尝试下一个子节点。因此，角色会移动到门前，打开门，然后进入房间。 |
| This example shows an important feature of behavior trees: a Condition task in a Sequence acts like an IF-statement in a programming language. If the Condition is not met, then the Sequence will not proceed beyond that point. | 这个例子展示了行为树的一个重要特性：序列中的条件任务就像编程语言里的 IF 语句。如果条件不满足，那么序列就不会继续执行到该点之后的任务。 |
| If the Sequence is in turn placed within a Selector, then we get the effect of IF-ELSE-statements: the second child is only tried if the Condition wasn't met for the first child. | 如果这个序列又被放在选择器中，那么我们就得到了类似 IF-ELSE 语句的效果：只有当第一个子节点中的条件不满足时，才会尝试第二个子节点。 |
| In pseudo-code the behavior of this tree is: if isLocked(door), moveTo(door), open(door), moveTo(room), else moveTo(room). | 用伪代码表示，这棵树的行为大致是：如果门被锁住，就移动到门前、开门、移动进房间；否则直接移动进房间。 |
| The pseudo-code and diagram show that we're using the final move action in both cases. There's nothing wrong with this. Later on in the section we'll look at how to reuse existing subtrees efficiently. | 伪代码和图示表明，在两种情况下我们都使用了最后那个移动动作。这本身没有问题。本节后面会讨论如何高效地复用已有子树。 |
| For now it is worth saying that we could refactor our behavior tree to be more like the simpler pseudo-code. The result is shown in Figure 5.26. Notice that it is deeper than before; we've had to add another layer to the tree. | 目前值得指出的是，我们可以重构这棵行为树，让它更接近更简洁的伪代码。结果如图 5.26 所示。注意它比之前更深，因为我们不得不向树中增加另一层结构。 |
| While some people do like to think about behavior trees in terms of source code, it doesn't necessarily give you any insight in how to create simple or efficient trees. | 虽然有些人确实喜欢用源代码的方式思考行为树，但这种思考方式并不一定能帮助你创建简单或高效的树。 |
| In our final example in this section we'll deal with the possibility that the player has locked the door. In this case, it won't be enough for the character to just assume that the door can be opened. Instead, it will need to try the door first. | 在本节最后一个例子中，我们会处理玩家已经把门锁上的可能性。在这种情况下，角色不能简单地假设门一定可以被打开；相反，它需要先尝试开门。 |
| Figure 5.27 shows a behavior tree for dealing with this situation. Notice that the Condition used to check if the door is locked doesn't appear at the same point where we check if the door is closed. | 图 5.27 展示了一棵用于处理这种情况的行为树。注意，用于检查门是否上锁的条件，并没有出现在检查门是否关闭的同一个位置。 |
| Most people can't tell if a door is locked just by looking at it, so we want the enemy to go up to the door, try it, and then change behavior if it is locked. In the example, we have the character shoulder charging the door. | 大多数人不能只靠看一眼就判断门是否上锁，因此我们希望敌人走到门前，先尝试一下；如果发现门锁住了，再改变行为。在这个例子中，角色会用肩膀撞门。 |
| I won't walk through the execution of this behavior tree in detail. Feel free to step through it yourself and make sure you understand how it would work if the door is open, if it is closed, and if it is locked. | 我不会详细逐步讲解这棵行为树的执行过程。你可以自己一步步推演，确保理解当门打开、门关闭以及门上锁时，它分别会如何工作。 |
| At this stage we can start to see another common feature of behavior trees. Often they are made up of alternating layers of Sequences and Selectors. | 到这个阶段，我们可以开始看到行为树的另一个常见特征：它们往往由序列和选择器交替构成多层结构。 |
| As long as the only Composite tasks we have are Sequence and Selector, it will always be possible to write the tree in this way. Even with the other kinds of Composite tasks we'll see later in the section, Sequence and Selector are still the most common, so this alternating structure is quite common. | 只要我们拥有的组合任务只有序列和选择器，就总是可以用这种方式写出行为树。即使后面会看到其他类型的组合任务，序列和选择器仍然是最常见的，因此这种交替结构也非常常见。 |
| We are probably just about at the point where our enemy's room-entering behavior would be acceptable in a current generation game. There's plenty more we can do here. | 到这里，敌人进入房间的行为大概已经接近当前世代游戏可以接受的程度了。当然，我们仍然可以继续扩展许多内容。 |
| We could add additional checks to see if there are windows to smash through. We could add behaviors to allow the character to use grenades to blow the door, pick up objects to barge the door, or pretend to leave and lie in wait for the player to emerge. | 我们可以增加额外检查，判断是否有窗户可以砸开进入；也可以添加行为，让角色使用手雷炸门，捡起物体撞门，或者假装离开并埋伏等待玩家出来。 |
| Whatever we end up doing, the process of extending the behavior tree is exactly as I've shown it here, leaving the character AI playable at each intermediate stage. | 无论最终添加什么内容，扩展行为树的过程都与这里展示的一样：在每一个中间阶段，角色 AI 都仍然是可玩的。 |

## Behavior Trees and Reactive Planning / 行为树与反应式规划

| English | 中文翻译 |
| --- | --- |
| Behavior trees implement a very simple form of planning, sometimes called reactive planning. Selectors allow the character to try things, and fall back to other behaviors if they fail. | 行为树实现了一种非常简单的规划形式，有时称为反应式规划。选择器允许角色尝试某些行为，并在失败时退回到其他行为。 |
| This isn't a very sophisticated form of planning: the only way characters can think ahead is if you manually add the correct conditions to their behavior tree. Nevertheless, even this rudimentary planning can give a good boost to the believability of your characters. | 这并不是一种非常复杂的规划方式：角色能够“提前思考”的唯一方式，是你手动把正确的条件加入它的行为树中。尽管如此，即使这种基础的规划，也能显著提升角色的可信度。 |
| The behavior tree represents all possible Actions that your character can take. The route from the top level to each leaf represents one course of action, and the behavior tree algorithm searches among those courses of action in a left-to-right manner. In other words, it performs a depth-first search. | 行为树表示角色可以采取的所有可能动作。从顶层到每个叶子节点的路径都代表一种行动方案，而行为树算法会按照从左到右的方式在这些行动方案中搜索。换句话说，它执行的是深度优先搜索。 |
| There is nothing about behavior trees or depth-first reactive planning that is unique, of course; we could do the same thing using other techniques, but typically they are much harder. | 当然，行为树或深度优先的反应式规划本身并不是唯一能做到这一点的技术；我们也可以用其他技术实现相同效果，但通常会困难得多。 |
| The behavior of trying doors and barging through them if they are locked, for example, can be implemented using a finite state machine. But most people would find it quite unintuitive to create. | It would be fairly easy to write a script for this particular effect, but we'll soon see behavior trees that are difficult to turn into scripts without writing lots of infrastructure code to support the way behavior trees naturally work. | 对于这个特定效果，直接写脚本也许相当容易。但我们很快会看到一些行为树，如果不编写大量基础设施代码来支持行为树天然的工作方式，就很难把它们转换成普通脚本。 |
